## U-B1 — Documentation infrastructure (no business changes)
1. Serve the reference UIs from the generated document, exactly as `api-conventions.md` §5 describes:
   - `/docs` → **Scalar** via `@scalar/nestjs-api-reference` (current major): layout grouped by surface tags, dark mode following the system, "try it" limited to the sandbox server entry, client snippets for `fetch`, `curl` and Node.
   - `/docs/swagger` → Swagger UI (`@nestjs/swagger`), `/docs-json`, `/docs.yaml`.
   - Gate: always on in local/dev; elsewhere only with `DOCS_ENABLED=true` **and** staff authentication (or an IP allow-list from env). Production default off. The raw document never exposes internal-only operations (mark them `@ApiExcludeEndpoint()` or split tags).
   - Document-level: `info` (title "getpack API", version from `package.json`, description restating money/date formats and the error model), `servers` (local, integration, sandbox, production), tag descriptions per surface, security schemes per audience (`customer`, `staff`, `partner`, `client_credentials`), shared components (`Problem`, `ValidationProblem`, pagination envelopes, money string, date-time).
2. Reusable decorators in `src/common/docs/`: `@ApiStandardErrors(...codes)` (maps problem `code`s → documented 4xx/5xx with examples), `@ApiPaginated(Dto)`, `@ApiCursor(Dto)`, `@ApiIdempotent()` (header + replay semantics), `@ApiConcurrency()` (`If-Match`/`ETag` + 412), `@ApiRateLimited()` (429 + `Retry-After` + rate-limit headers), `@ApiAsync()` (202 + polling link), `@ApiDecision('D-###')` (appends the decision id to the description), `@ApiFileUpload()` (presign flow). Example builders with obviously fake data (`Somchai Test`, `0800000000`, `test@example.com`, tax id `0000000000000`).
3. Webhooks: declare every inbound provider callback (SCB, 2C2P, slip verification, carriers, LINE, Facebook) in OpenAPI 3.1 `webhooks` with payload schema, signature header and the response the provider expects.
4. **Spectral** ruleset `contract/.spectral.yaml` + `pnpm contract:lint`: fail when an operation lacks `operationId` (pattern `^(auth|store|admin|partner|webhooks)\.[a-z][A-Za-z]+\.[a-z][A-Za-z]+$`), `summary`, `description`, tag, security (except `@Public()` routes, which must say so), a success response with example, the documented error set for its kind (all: 400/401/403/404/429/500; mutations add 409/422; `If-Match` operations add 412; async add 202), examples on every request/response body; fail on inline enums, `type: object` without properties or `additionalProperties`, duplicated schema shapes, money fields typed as number, and examples matching real-looking PII patterns (Thai mobile numbers other than `08000000xx`, real-looking tax ids, non-`example.com` emails).
5. **Baseline, then ratchet**: run the ruleset over today's document, write `contract/lint-baseline.json` (violations keyed by operationId + rule). CI fails on any violation **not** in the baseline and on any baseline growth; the baseline shrinks as U-B2 progresses and must be empty before U-B2 is done. `pnpm contract:lint --report` prints remaining violations per module.
6. Add to `CLAUDE.md` (if missing) the rule: every endpoint change runs `pnpm contract:build` **and** `pnpm contract:lint` and commits `contract/openapi.json`; every operation needs operationId, summary, description with its decision id, security, the full status-code set and examples.
7. Acceptance: `/docs` renders Scalar, `/docs/swagger` renders, `/docs.yaml` valid, gating tests (prod without flag → 404; with flag and no staff token → 401), `pnpm contract:lint` green against the baseline, contract regenerated and committed, `docs/PROGRESS.md` entry.

## U-B3 — Pricing ownership, tiers, quote paths, price-data protection (D-042, D-043, D-044) — gap check
Mostly built in B2.2; tier-B envelopes are delivered at the end of U-B6. Run this session only to verify the items below and fix gaps (price-data protection tests, access log, k ≥ 3, deprecated "cost" naming); skip the migration review gate if no data migration is needed.
**Review gate:** after the gap analysis, implement the migration in dry-run mode and **stop** with `docs/update-2026-09-29-pricing-migration.md` for the user's review; continue only after approval.
1. **Schema** (per `docs/schema-design.md` conventions; update that document in the same commit):
   - `factory_pricing_arrangements` (factory, `ownership_mode` enum `platform_rate_card | factory_price_list`, effective-dated, changed with approval).
   - `factory_participation_tiers` (factory × product type, tier enum `A | B | C`, **tier-B envelope**: the spec dimensions it covers — size ranges / standard sizes / materials / print options / stock SKUs — as structured JSON validated by a schema per product type; effective-dated; audited).
   - Price-table versions gain `ownership_mode_at_creation`, `status` (`draft | proposed | awaiting_factory_acceptance | accepted | rejected | superseded`), per-line acceptance (`accepted | exception_requested | exception_agreed`), acceptance evidence (who, when, IP/UA, version hash).
   - `price_table_access_log` (actor, factory, table/line ids, purpose, at) — or reuse `audit_logs` with a dedicated action if that is already indexed for this query.
2. **Migration of existing data** (dry-run first): for each existing factory set `ownership_mode` = `platform_rate_card` when its current tables were entered by staff on its behalf (assisted onboarding sign-off present), else `factory_price_list`; compute the tier per product type from table completeness against that calculator's required inputs (complete → A; partial → B with the envelope derived from the lines present; none → C). The report lists every factory × type with the computed mode/tier, the missing lines behind any B/C, and which product types would **stop being instant** after the change. No data is deleted.
3. **Workflows**: `factory_price_list` — factory proposes → getpack reviews (suggestions + impact simulation, staff-only) → approve/reject/counter → effective. `platform_rate_card` — getpack drafts a version → sends to factory → factory accepts all / accepts with per-line exceptions / requests change → the version applies to **new** quotes from `effective_from` only after acceptance. Both via the approvals engine; events `pricing.version.*`, `pricing.acceptance.*`.
4. **Quote-path resolution service** (`pricing/quote-path.service.ts`): given product type + configuration (+ delivery zone, date) → `{ mode: 'instant' | 'rfq', eligibleFactories[], reason }`; instant only when ≥ 1 active factory has tier A for the type, or tier B whose envelope covers the configuration, **and** capability + capacity. Used by: `POST /v1/store/quotes` (returns a typed `rfq_required` result with reason instead of a price when no path exists — documented, not an error), CS calculate, cart re-pricing, reorder, factory selection in B2.3 (only factories with a covering path are ranked), and a new `GET /v1/store/catalog/types/{typeId}/availability` (instant / rfq / partial with the envelope summary customers may see — no factory identity).
5. **Price-data protection** (D-044): partner endpoints return only the caller's own factory data and **never** suggestions, benchmarks or other factories' values (add contract tests that assert the absence of these fields); staff reads of another factory's price lines are permission-checked (D-141) and logged with purpose; exports and the partner prospectus aggregate only with **k ≥ 3** per breakdown (D-160, setting `analytics.prospectus_min_group_size`; suppress or merge smaller cells); peer benchmarks computed only when ≥ 3 active factories serve the type.
6. **Terminology**: factory buy prices are "price / buyPrice / priceTable" in routes, DTOs, enums, events and settings — not "cost". Rename additively: add the new routes/fields, keep the old ones working with `deprecated: true`, a `Deprecation` + `Sunset` header and a log counter; removal happens in U-B5. Keep "cost" where it is correct accounting language (cost of sales, effective cost to Collective Group in selection).
7. **Admin coverage map** endpoint: per product type → factories and their tier, envelope summary, instant coverage % of the last 90 days' configurations (from calculate/search logs), RFQ volume — for the partner team (D-043) and the demand dashboard (D-102).
8. Tests: migration dry-run on fixtures; quote-path matrix (A / B covering / B not covering / C / no capacity / inactive factory); store quote returns `rfq_required`; partner cannot read suggestions or other factories (IDOR); access log written; k-anonymity suppression in prospectus; deprecated routes still pass their old contract tests.
