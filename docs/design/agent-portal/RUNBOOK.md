# คู่มือปฏิบัติงานโปรแกรมตัวแทนขาย getpack — Agent programme runbook

> ผู้ใช้: Finance Manager, Finance, Sales Manager, C-Level, DPO, Superadmin · ระบบ: `getpack-api` + admin zone
> อ้างอิงมติ D-416–D-423, D-464–D-472 และ PLAN §5 · เวลาทั้งหมดเป็นเวลา Asia/Bangkok
> ข้อเท็จจริงด้านภาษีที่ยังต้องให้ผู้สอบบัญชี / CPA ยืนยันทำเครื่องหมาย **(ยืนยันกับ CPA)** ไว้

## 1. Monthly statement day — วันสรุปค่าคอมประจำเดือน (วันที่ 1)

**ระบบทำเอง**

- ทุกชั่วโมง job `agents.earn`: รายการ `pending` ที่พ้นช่วงเคลม และ order group ชำระครบแล้ว → `earned`
- วันที่ 1 เวลา 10:00 (cron `0 3 1 * *` UTC) job `agents.statements`: สร้างใบสรุป (`AG<yy><mm>-<code>`) ต่อตัวแทน
  จากรายการ `earned` ที่ยังไม่อยู่ในใบสรุปถึงสิ้นเดือนก่อน; ยอดสุทธิ ≤ 0 ยกไปเดือนถัดไป (ไม่มีใบสรุป)
- ตัวแทนอิสระที่ยังไม่มีข้อมูลรับเงินที่ตรวจแล้ว: ใบสรุปเป็นร่าง ติดธง `payout_profile_missing` ระบบแจ้งตัวแทน (in-app +
  e-mail) — ไม่มีเงินหาย ยอดสะสมรอไว้

**ตรวจก่อนอนุมัติ (Finance Manager, วันที่ 1–3)**

1. Admin → ตัวแทน → ใบสรุป → เดือนล่าสุด: จำนวนใบสรุปเท่ากับจำนวนตัวแทนที่มียอด `earned` (ถ้าไม่ครบ ดู log ของ job
   `agents.statements` — ข้อความ "statement for agent … not generated" แล้วกด "ออกใบสรุป" ซ้ำ: `admin.agents.generateStatements`
   ทำซ้ำได้ ไม่ซ้ำซ้อน)
2. รายการถูกพัก (`held`, เช่น `phone_match`) ตัดสินก่อน: ปล่อยหรือยกเลิกพร้อมเหตุผล (`admin.agents.decideHeldCommission`)
3. รายการติดธง `margin_alert` (ค่าคอม ÷ กำไรขั้นต้น > `agent.margin_alert_pct`) — **ไม่ลดค่าคอม** (D-464) แจ้งผู้บริหารเท่านั้น
4. ตัวแทนนิติบุคคลที่จด VAT: ต้องแนบใบกำกับภาษีของตัวแทนก่อน (`admin.agents.attachStatementTaxInvoice`) มิฉะนั้นอนุมัติไม่ได้
   (`agent_statements.tax_invoice_required`) — ตรวจเลขผู้เสียภาษี สาขา ยอดก่อน VAT และ VAT 7 % ให้ตรงกับใบสรุป
5. ตัวแทนบุคคลธรรมดา: ตรวจ ล.ย.01 ของปีภาษีที่ส่งเข้ามา (รับ / ปฏิเสธพร้อมเหตุผล) **ก่อน**อนุมัติ เพราะการหักภาษีคำนวณ
   ณ วันอนุมัติจากใบที่รับแล้วล่าสุดของปี

**อนุมัติ (Finance Manager)** — `admin.agents.approveStatement` (If-Match)

- อิสระ บุคคลธรรมดา: ระบบคำนวณภาษีหัก ณ ที่จ่ายแบบอัตราก้าวหน้า ม.50(1) สะสมทั้งปี (D-465) แล้วบันทึกเป็นใบแจ้งหนี้ผู้ขาย
  (บัญชี 6160) จำนวนภาษีที่หักเก็บใน payable item (`wht_commission_fixed`) — รอบจ่ายหักตามจำนวนนี้พอดี ไม่ใช้อัตราคงที่
- อิสระ นิติบุคคล: หัก 3 % เมื่อยอด ≥ ฿1,000.00 (ภ.ง.ด.53) + VAT 7 % บนใบแจ้งหนี้ถ้าจด VAT
- พนักงาน: บันทึก Dr 6160 / Cr 2410 แล้ว export CSV ให้ payroll (`admin.agents.exportPayroll`) ภาษีไปตาม ภ.ง.ด.1 ของเงินเดือน
- ใบสรุปที่ผิด: ยกเลิก (`admin.agents.voidStatement`, เหตุผล) — รายการกลับเป็น `earned` แล้วออกใบใหม่

**จ่ายเงิน (Finance + C-Level)**

1. Finance สร้างรอบจ่าย (`admin.payouts.create`) เลือกใบแจ้งหนี้ค่านายหน้า (`AG…`) ที่ครบกำหนด (`agents.rules.paymentTermsDays`
   นับจากวันอนุมัติ) → เสนอ (`propose`)
2. C-Level อนุมัติ (คนละคนกับผู้เสนอ) → สร้างไฟล์ธนาคาร (`generateBankFile`) → อัปโหลดเข้า internet banking
3. เมื่อธนาคารแจ้งผล: `admin.payouts.confirm` ระบุรายการที่สำเร็จ / ล้มเหลว → ใบสรุปเปลี่ยนเป็น `paid` ตามรายการที่จ่ายแล้ว
   ระบบออก 50 ทวิ ต่อรายการที่จ่ายและมีภาษีหัก (ยอดหัก > 0) แล้วแจ้งตัวแทน (`payout_paid`)

## 2. WHT filing — การยื่นภาษีหัก ณ ที่จ่าย

| ผู้รับเงิน | เงินได้ | แบบ | กำหนด | บัญชี |
|---|---|---|---|---|
| ตัวแทนอิสระ บุคคลธรรมดา | ค่านายหน้า ม.40(2) หักตาม ม.50(1) อัตราก้าวหน้า | **ภ.ง.ด.1** รายเดือน | ภายในวันที่ **7** ของเดือนถัดจากเดือนที่จ่าย (ยื่นกระดาษ); ยื่นทางอินเทอร์เน็ตได้รับขยายเวลาอีก 8 วัน **(ยืนยันกับ CPA ว่าประกาศขยายเวลายังมีผลในปีนั้น)** | Cr 2233 |
| ตัวแทนอิสระ บุคคลธรรมดา | สรุปทั้งปี | **ภ.ง.ด.1ก** | ภายใน**สิ้นเดือนกุมภาพันธ์**ของปีถัดไป (รวมทุกคนที่จ่ายเงินได้ ม.40(1)/(2) ในปี) | — |
| ตัวแทนอิสระ นิติบุคคล | ค่าบริการ / ค่านายหน้า 3 % | **ภ.ง.ด.53** | ภายในวันที่ **7** ของเดือนถัดไป; e-filing +8 วัน **(ยืนยันกับ CPA)** | Cr 2231 |
| ตัวแทนพนักงาน | ม.40(1) รวมกับเงินเดือน | ภ.ง.ด.1 ผ่าน payroll | ตาม payroll | Cr 2410 (ค้างจ่าย) |

ขั้นตอนทุกเดือน (Finance, วันที่ 1–7):

1. Admin → ภาษี → สร้างรายงานของงวดเดือนก่อน (`admin.tax.generate`) แบบ `pnd1` และ `pnd53` — ระบบดึงจาก 50 ทวิ ที่ออก
   ในเดือนนั้นเทียบกับยอดบัญชี 2233 / 2231
2. ตรวจผลต่างเป็นศูนย์ → ปิดรายงาน (`finalise`) → export ไฟล์แนบ (`export`) → ยื่นที่ระบบ e-Filing ของกรมสรรพากร
3. บันทึกการยื่น (`admin.tax.file`: วันที่, เลขอ้างอิง, ยอด) และการชำระ (`admin.tax.pay`)
4. ตัวแทนนิติบุคคลที่จด VAT: ภาษีซื้อจากใบกำกับภาษีของตัวแทนเข้า ภ.พ.30 ของงวดที่ได้รับใบกำกับ (ภายในวันที่ 15; e-filing
   ภายในวันที่ 23 **(ยืนยันกับ CPA)**)
5. **ข้อควรทำ:** setting `tax.calendar` ยังไม่มีแถว `pnd1` (มีแต่ `pp30`, `pnd3`, `pnd53`) — Finance Manager เพิ่มเวอร์ชันใหม่
   `pnd1: { dayOfNextMonth: 7 }` เพื่อให้ระบบเตือนกำหนดยื่น ภ.ง.ด.1 (ยังไม่ได้ทำใน P7 เพราะเป็นค่าที่ Finance ต้องอนุมัติ)

ทุกปี (Finance Manager, มกราคม–กุมภาพันธ์):

1. ใบสรุปเดือนธันวาคมคำนวณแบบปรับยอดจริง (projected = YTD) — ตรวจว่าภาษีสะสมทั้งปีตรงกับภาษีตามตาราง
2. จัดทำ ภ.ง.ด.1ก จากทะเบียน 50 ทวิ ประเภท "ค่านายหน้า 40(2)" ทั้งปี ยื่นภายในสิ้นเดือนกุมภาพันธ์
3. แจ้งตัวแทน: สูตรไม่คืนภาษีระหว่างปี ถ้าเดือนหลังๆ ยอดต่ำกว่าที่คาด ตัวแทนอาจถูกหักเกิน และขอคืนได้เมื่อยื่น ภ.ง.ด.90
4. ตรวจตารางภาษี `tax.pit_brackets`, `tax.wht_40_2.*` สำหรับปีใหม่ (มีผลตามวันที่) **(ยืนยันกับ CPA)**

## 3. 50 ทวิ issuance — การออกหนังสือรับรองการหักภาษี ณ ที่จ่าย

- ออกโดยระบบเมื่อรายการในรอบจ่ายถูกยืนยันว่าจ่ายแล้วและมีภาษีหัก (> 0) หนึ่งฉบับต่อการจ่าย (บุคคลที่คำนวณแล้วภาษีเป็น 0 ไม่มี 50 ทวิ ของเดือนนั้น แต่ยังรวมเงินได้ใน ภ.ง.ด.1ก **(ยืนยันกับ CPA)**) ประเภทเงินได้ "ค่านายหน้า 40(2)" (บุคคล, ทำเครื่องหมาย
  ภ.ง.ด.1ก) หรือ ค่าบริการ (นิติบุคคล, ภ.ง.ด.53); เลขที่ตาม series `wt`
- ตัวแทนดาวน์โหลดเองในโซนตัวแทน (`store.agent.whtCertificate`) — รวมถึงตัวแทนที่สิ้นสุดแล้ว ภายใน
  `agents.ended_record_access_years` (5 ปี)
- **ก่อนเปิด public:** ต้องเติมชื่อนิติบุคคล เลขประจำตัวผู้เสียภาษี สาขา ที่อยู่ของ Collective Group ใน settings ของ entity
  (ข้อมูลบริษัทมาจาก settings เท่านั้น) — 50 ทวิ ที่ออกก่อนเติมข้อมูลถือว่าใช้ไม่ได้
- ใบที่ออกผิด: ห้ามแก้ไฟล์ ให้ยกเลิกและออกใหม่ตามขั้นตอนเอกสารภาษีของ Finance พร้อมบันทึกเหตุผล **(ยืนยันกับ CPA)**

## 4. Payout failures — การจ่ายไม่สำเร็จ

| อาการ | สาเหตุที่พบบ่อย | ทำอย่างไร |
|---|---|---|
| ธนาคารตีกลับรายการ (`failed`) | เลขบัญชีผิด, บัญชีปิด, ชื่อไม่ตรง | `admin.payouts.confirm` ระบุรายการล้มเหลวพร้อมเหตุผล → รายการเข้าคิว "รายการค้างจ่าย" (`admin.payouts.exceptions`) → ติดต่อตัวแทนให้แก้ข้อมูลรับเงิน → Finance Manager ตรวจใหม่ → ใส่ในรอบจ่ายถัดไป ใบสรุปยัง `approved` จนจ่ายสำเร็จ |
| ชื่อบัญชีไม่ตรงชื่อตามกฎหมาย | ตัวแทนแก้ข้อมูลเอง | ระบบไม่ให้ส่ง (`agents.bank_name_mismatch`) ตัวแทนต้องใช้บัญชีชื่อตนเอง / ชื่อบริษัท |
| ข้อมูลรับเงินถูกแก้หลังตรวจ | ตัวแทนเปลี่ยนบัญชี | ข้อมูลใหม่เป็นร่างรอตรวจ ใบสรุปใหม่ติดธง `payout_profile_missing`; บัญชีใหม่ผ่าน dual approval ของบัญชีผู้ขาย (B5.3) ก่อนใช้จ่าย |
| ใบสรุปอนุมัติไม่ได้ `agents.payout_profile_missing` | ยังไม่มีข้อมูลรับเงินที่ตรวจแล้ว | แจ้งตัวแทน ระบบปล่อยธงเองเมื่อ Finance ตรวจผ่าน |
| ยอดภาษีหักในรอบจ่ายไม่ตรงใบสรุป | payable item ถูกแก้ด้วยมือ | ห้ามแก้ ยกเลิกใบสรุปแล้วอนุมัติใหม่ |

ห้ามโอนเงินนอกระบบ ทุกการจ่ายต้องผ่านรอบจ่ายเพื่อให้มี 50 ทวิ และรายการบัญชีครบ

## 5. Agent offboarding — การสิ้นสุดตัวแทน

1. Sales Manager: Admin → ตัวแทน → "สิ้นสุด" พร้อมเหตุผล (`admin.agents.end`) ระบบจะ
   - ปิดลิงก์ลูกค้าทั้งหมด (`agent_ended`) — ออเดอร์หลังจากนี้ไม่มีค่าคอม
   - ลูกค้ามุ่งหวังที่ยังคุ้มครองหมดอายุทันที และการจดทะเบียนดีล (deal registration) หมดอายุทันที (P7) — ตัวแทน / พนักงานคนอื่นรับต่อได้
   - ค่าคอมที่เกิดแล้วยังจ่ายตามปกติ (ใบสรุปเดือนถัดไป)
2. ลูกค้าเดิมของตัวแทน: ถ้าต้องให้พนักงานขายดูแลต่อ ใช้ "มอบหมาย" (`admin.agents.assignLink`) ไปยังตัวแทนพนักงานพร้อมเหตุผล
3. Finance: ตรวจว่าไม่มีรายการค้าง (`held`, ใบสรุปร่าง) แล้วปิดงานจ่ายเดือนสุดท้าย; vendor ของตัวแทนไม่ต้องลบ (ประวัติ)
4. การเข้าถึงของตัวแทน: ทุกเมนูปิด (403 `agents.ended`) ยกเว้นใบสรุปและ 50 ทวิ อ่านได้ 5 ปี (`agents.ended_record_access_years`)
5. เก็บเอกสาร: ใบสรุป ใบแจ้งหนี้ 50 ทวิ ข้อมูลรับเงิน และหลักฐานการยอมรับสัญญา เก็บอย่างน้อย 5 ปีนับจากปีที่จ่าย
   (`documents.retention_years`; พ.ร.บ. การบัญชี / ประมวลรัษฎากร **(ยืนยันกับ CPA ว่าคดีภาษีอาจขยายเกิน 5 ปี)**)
6. ตัวแทนพนักงานที่ลาออก: สิ้นสุดตัวแทนในวันเดียวกับวันพ้นสภาพ และถอนสิทธิ์บัญชี staff (`sales_rep`) ตามขั้นตอน HR

## 6. Data subject requests — คำขอของเจ้าของข้อมูล (PDPA)

ตอบภายใน `privacy.response_days` (30 วัน) โดย DPO (`admin.privacyRequests.*`, D-222)

| คำขอ | ทำอย่างไร |
|---|---|
| ขอดู / ขอสำเนา (ตัวแทน) | DPO ทำคำขอ export ของบัญชี; เพิ่มข้อมูลตัวแทนด้วยมือจาก admin: ใบสมัคร, ข้อมูลรับเงิน (เลขบัญชีแสดง 4 หลักท้าย), ล.ย.01, ลูกค้ามุ่งหวังที่ตัวแทนบันทึก, ใบสรุป ลิงก์ดาวน์โหลดมีอายุ `privacy.export_link_days` (7 วัน) |
| ขอลบ / ทำให้ไม่ระบุตัวตน (ตัวแทน) | สิ้นสุดตัวแทนก่อน (§5) → ระบบทำให้บัญชีไม่ระบุตัวตน (ชื่อ อีเมล โทรศัพท์ ที่อยู่ session และ hand-off code ถูกลบ) **ยกเว้น**เอกสารภาษีและบัญชี (ชื่อตามกฎหมาย เลขผู้เสียภาษี ใบสรุป 50 ทวิ) ที่ต้องเก็บตามกฎหมาย ให้แจ้งข้อจำกัดนี้ในคำตอบ; ถ้ามีออเดอร์ / เคลม / ลูกหนี้ค้าง ระบบปฏิเสธจนกว่าจะปิด |

## 7. Pilot switch — การเปิดโปรแกรมแบบนำร่อง

ค่าตั้งต้น: ทุกอย่าง**ปิด** (flag `agents.programme` = off, setting `agents.pilot.enabled` = false)

1. **เพิ่มผู้นำร่อง** (Sales Manager): Admin → Settings → `agents.pilot` → เวอร์ชันใหม่ `{ "enabled": true, "userIds": [<public id
   ของบัญชีลูกค้า>, …] }` มีผลตามวันที่กำหนด ระบบบันทึก audit ทุกเวอร์ชัน — บัญชีในรายชื่อเห็นปุ่มสมัคร (`applyOpen: true`)
   คนอื่นยังเห็น "ลงทะเบียนรอเปิดรับ"
2. **หยุดนำร่องชั่วคราว**: เวอร์ชันใหม่ `enabled: false` — ใบสมัครที่ส่งแล้วยังพิจารณาได้ ตัวแทนที่อนุมัติแล้วยังทำงานได้
3. **ดูรายชื่อรอเปิดรับ**: Admin → ตัวแทน → รายชื่อรอเปิดรับ (`admin.agentWaitlist.list` / `export` CSV) — ติดต่อเฉพาะผู้ที่ยินยอม
   ตามช่องทางที่เลือก
4. **เปิด public** (C-Level, หลังผ่าน checklist ก่อนเปิดรับสมัคร: สัญญา v2 ผ่านทนายและ publish, ข้อมูลบริษัทใน 50 ทวิ, VAPID / LINE OA,
   DNS `agent.getpack.co`, pilot 60 วันผ่าน KPI ใน PLAN §4): Superadmin เปิด flag `agents.programme` (ไม่มี rules) — `applyOpen` เป็น
   true สำหรับทุกคน แล้วตั้ง `agents.pilot.enabled = false`
5. **ปิดฉุกเฉิน**: Superadmin ปิด flag `agents.programme` และ Sales Manager ตั้ง `agents.pilot.enabled = false` — การสมัครใหม่ตอบ
   `agents.programme_closed` ทันที (cache 30 วินาที)
